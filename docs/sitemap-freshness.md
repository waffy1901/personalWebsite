# Sitemap freshness policy

`main/public/sitemap.xml` is generated by `npm run generate:public`. Its HTML
URL inventory comes from `main/src/data/seo.js`, using canonical lowercase
routes with trailing slashes. The existing `llms.txt`, `ai-summary.txt`, and
`portfolio.json` URLs remain in the sitemap.

Each entry contains only `loc`. Google ignores `priority` and `changefreq`, so
the generator omits both. Google uses `lastmod` when it consistently represents
a verifiable, significant change to the page. See
[Google Search Central's sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
and the [sitemaps.org XML protocol](https://www.sitemaps.org/protocol.html), where
these metadata fields are optional.

The current content model has no trustworthy per-route modification provenance.
A page draws from route data, shared data, components, and assets; the AI-readable
resources also combine shared data. Build or deployment timestamps describe
publication work, filesystem modification times describe file operations, and a
repository-wide commit date may describe an unrelated change. None establishes
when an individual page's substantive content changed. The portfolio's content
review date and employment or case-study dates do not establish that either.

For Issue #176 (F-020), `lastmod` is deliberately omitted rather than introducing
disproportionate date-tracking complexity or emitting misleading freshness.
Future `lastmod` support would need an explicit, maintained source of substantive
per-URL change dates, covering shared dependencies and generated resources, with
validation for format, provenance, and plausible dates. A rebuild alone must not
advance those dates.

`main/scripts/sitemap.mjs` parses the sitemap as XML using the existing jsdom
development dependency, without external resource loading or script execution.
It rejects DTDs, malformed XML, incorrect namespaces or entry structure,
noncanonical URLs, duplicate URLs, missing or extra URLs, and all unsupported
entry metadata (including `lastmod`). Generation validates the intended XML;
`npm run generate:public -- --check` also validates the checked-in XML before
checking generated freshness. Regression tests cover those contracts and output
stability across changed deployment-date environments.

These checks establish local artifact correctness. They do not prove a production
deployment, crawler retrieval, indexing, or ranking changes.
